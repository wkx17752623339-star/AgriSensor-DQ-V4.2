# AgriSensor-DQ V4.1 速度优化版

## 本版主要变化
- 保留原七个页面、P0/P1/P2、节点独立自适应检测与科研浅色界面。
- `app.py`：仅在总览、节点、质量、报告页面计算全量诊断；数据管理、故障诊断、算法实验页面不再被首页的全量检测阻塞。使用 `st.cache_data` 缓存标准化和检测结果。数据集变化会触发新的缓存键。
- `engine.py`：历史同时段基线按节点内时段/日期批量累计；仅使用以前日期的数据，不使用当前或未来日期。漂移检测采用滚动OLS封闭公式。
- 本版没有合并所有模块到单文件：UI、算法和实验服务仍独立，便于维护；已删除重复版本说明，避免无意义拆分。

## 性能对比（本次运行环境；6节点12,000条CSV；单次冷计算）
| 算法 | 旧版 | 优化版 | 标记差异 |
|---|---:|---:|---:|
| 场景自适应 | 14.284 s | 0.191 s | 0 |
| 漂移检测 | 0.281 s | 0.025 s | 0 |
| 综合检测 | 13.437 s | 0.334 s | 0 |

上述为计算层测试，不代表浏览器整页耗时；实际页面还取决于机器、Plotly渲染、浏览器和缓存状态。自适应基线及上下界与旧版逐值一致（最大差异0）。

## 本地运行
进入包含 `app.py` 的目录：
```
python -m pip install -r requirements.txt
python -m streamlit run app.py
```
首次运行仍需加载数据、建立缓存；再次切换页面通常更快。可用 Ctrl+C 停止。

## GitHub / Streamlit Cloud
先备份当前稳定仓库，建议新建测试分支验证本版。保持 `AgriSensor-DQ-V2/app.py` 作为应用入口，依赖位于 `AgriSensor-DQ-V2/requirements.txt`。在测试分支验证页面、上传、故障实验、报告后，再合并到 `main`。

## 限制
- Streamlit Cloud免费实例可能休眠；冷启动和浏览器首次图表渲染不能保证固定秒数。
- `st.cache_data` 会按内容计算哈希，上传大文件仍可能增加开销；对于12,000条样本适用。
- 云端会话数据和临时记录不保证持久化；这是历史样本分析系统，不是实时采集平台。
